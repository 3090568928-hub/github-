# 沉浸式翻译 + GitHub 汉化

本地构建工具，适配 Edge 版沉浸式翻译 **1.35.2** 和 GitHub 中文汉化翻译插件 **3.1.4**。生成的扩展有一个工具栏图标，面板顶部可切换「沉浸式翻译」和「GitHub 汉化」。

## 从仓库生成扩展

在 Windows 上安装 Node.js 22 或以上版本，并在 Edge 默认配置中准备好上述两个版本的扩展。运行以下命令即可在仓库旁生成可加载的 `translation-bundle-local` 文件夹。

```powershell
git clone https://github.com/3090568928-hub/github-.git
cd github-
node build.mjs --out ..\translation-bundle-local
```

如果扩展装在其他浏览器配置中，或已将原扩展解压到本地，请按下文「重新构建」中的示例指定两个输入目录。

## 安装本地合并版

1. 打开 `edge://extensions`，先关闭原来的两个扩展，防止同一页被处理两次。保留原扩展便于切回和导出已有设置。
2. 开启「开发人员模式」，点「加载解压缩的扩展」，选择生成的 **translation-bundle-local** 文件夹。该目录的第一层包含 `manifest.json`。
3. 刷新已经打开的网页。固定新扩展后，点击图标可以使用两个面板。GitHub 面板的「内容翻译设置」打开汉化插件的设置页。

Codex 内置浏览器使用独立的浏览器配置。如果它提供扩展管理界面，可在内置浏览器的 `chrome://extensions/` 中核对「沉浸式翻译 + GitHub 汉化」，本地合并版的 ID 是 `khpcnkicahklhbifadioigkkhbcjahaf`。从 ZIP 手动加载时先解压，选择包含 `manifest.json` 的目录。更新已加载的本地目录后，点扩展卡片上的「重新加载」，再刷新 GitHub 页面。[OpenAI 内置浏览器说明](https://help.openai.com/en/articles/20001277-using-the-built-in-browser-in-the-chatgpt-desktop-app)

打开 GitHub 仓库时，沉浸式翻译会自动处理英文正文，双语模式中的中文译文显示为原配置的红色 `#d32f2f`。GitHub 的导航、菜单和按钮由汉化模块处理。其他网页仍按各自的翻译设置工作。

「翻译」按钮可以直接翻译当前页面。合并版默认将这项操作的快捷键留空，方便继续用 `Alt+A` 微信截图。如果 Edge 保留了手动绑定，可在 `edge://extensions/shortcuts` 清除，或自行指定其他组合键。

更新旧版时，在扩展管理页重新加载更新后的目录，然后刷新 GitHub 标签页。首次运行新版时会将 GitHub 加入沉浸式翻译的自动翻译站点列表，并将原来的译文样式加入自定义 CSS。后续在沉浸式翻译设置中对这两项所做的修改会保留。目标语言和界面语言默认使用简体中文，升级时会沿用你已选的语言。

合并版有独立的扩展 ID。要沿用原来的服务、语言、样式和站点列表，可在原版沉浸式翻译的「设置 → 导入/导出」中导出文件，再到合并版的同一位置导入。导入会替换现有配置。备份是否包含服务凭据取决于导出选项，含凭据的文件请仅在本机使用。账号可以在合并版面板中重新登录。切回原扩展时，关闭合并版、重新打开原扩展并刷新页面即可。

GitHub 界面汉化开箱即可使用。如果原先还给 GitHub 汉化单独配置了 AI 服务，请在合并面板的「GitHub 汉化 → 内容翻译设置」中填回服务配置。这个模块的设置独立于沉浸式翻译备份。

合并版保留了沉浸式翻译的 32 条静态网络规则，规则仅处理合并版发起的请求。DeepL 的两条规则、腾讯交互翻译和火山翻译各一条规则会向服务发送合并版自己的扩展来源标识。如果对应服务限定了可用的扩展 ID，这些接口可能拒绝请求。

## 重新构建

需要 Node.js 22 或以上版本。默认从当前 Windows 用户的 Edge Default 配置读取上述两个版本的扩展程序文件。

```powershell
node build.mjs --out ..\translation-bundle-local
```

也可以显式指定原扩展的目录。每个输入目录的第一层都应包含其 `manifest.json`。输出路径的父目录须已存在，构建器会拒绝覆盖已有目录。

```powershell
node build.mjs --immersive "D:\extensions\immersive\1.35.2_0" --github "D:\extensions\github-chinese\3.1.4_0" --out "D:\extensions\translation-bundle-local"
```

构建器只读取安装目录里的扩展程序文件。后续商店升级不会自动更新合并版，升级构建输入时需要重新核对版本兼容性。

## 同页翻译

GitHub 汉化继续负责菜单和按钮，网页仍保留原始语言标记，沉浸式翻译可以识别英文正文。如果另行开启 GitHub 的 README 或 About 内容翻译，同一区域先写入的译文会保留。接口失败或没有返回有效译文时，该区域仍可由另一个引擎处理。

已在隔离的 Edge 157 中使用微软翻译联网对照。打开 `github.com/octocat/Spoon-Knife` 后，原版和合并版均自动翻译 README，保留英文原文。合并版在两份全新 Edge 配置中使用默认免费服务，首次打开 `octocat/Spoon-Knife` 和 `HKUDS/CLI-Anything` 即显示红色译文，全程未登录或点击「翻译」。仓库内切页和刷新另用固定译文核对了颜色。从原版设置页导出、在合并版导入的测试也恢复了目标语言、主题和自定义站点列表。

## 功能核对

| 功能 | 对照结果 |
| --- | --- |
| 网页双语和颜色 | 在同一个公开仓库联网测试，两个版本中的英文原文均为 `rgb(31, 35, 40)`，中文译文均为 `rgb(211, 47, 47)`。合并版使用微软翻译和谷歌翻译均获得了实际译文。重新加载合并版后，Codex 内置浏览器新开的 `octocat/Spoon-Knife` 页面也自动显示了英文原文、同色的红色中文译文和中文导航。 |
| GitHub 内容翻译 | 使用同一组固定的接口应答，对照了 README、About、仓库摘要，以及议题、拉取请求、讨论和发行版的原文、双语与仅译文切换。 |
| GitHub 协作与记录 | 已测试协作草稿润色并插入编辑框、翻译记录、缓存与调试日志。 |
| 划词、悬停、输入框和侧栏 | 合并版通过了免费服务的划词翻译联网测试。原版和合并版均通过 Ctrl 悬停、输入框 `Alt+I`、连续三次空格和侧栏文本翻译测试。 |
| 视频字幕 | 两个版本在带 WebVTT 字幕的视频测试页上，均保留时间码和英文字幕，并写入了本地翻译接口返回的中文字幕。 |
| 文档翻译 | 两个版本均能导出 TXT、HTML、EPUB、Markdown、SRT、WebVTT 和 ASS 双语文件。实际读取的字幕文件保留了时间码。MHTML 导出为双语 HTML，JSON 保留键并翻译值。两版使用免费微软翻译导出的 DOCX 也均包含英文和中文段落，本地测试接口生成的 DOCX 在两版均重复了英文。普通 PDF 阅读器可在未登录状态下显示双语正文。 |
| 图片翻译 | 两个版本的内置 OCR 均从同一张测试图识别出 `HELLO BOOKS`。点击单图翻译按钮后，两版均提示登录后可使用免费额度。登录后的云端图片重绘与付费文档服务尚未实测。 |
| 登录和自定义翻译服务 | 两个版本通过面板的「未登录」均能打开官方登录页，官网均识别到扩展版本 1.35.2。登录后的会话和个人服务密钥未作实测。 |

GitHub 汉化的 12 个服务选项均通过了配置地址与后台转发的匹配检查。Azure 接口支持同源重定向。如果服务需要跳到不同域名或端口，请直接填写最终接口地址，订阅密钥只发送给配置的来源。
